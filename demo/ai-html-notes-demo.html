What this replaces

The comprehensive-notes prompt used to dictate the layout, and the client rendered a fixed Markdown subset — so every lecture produced the same-looking notebook.

before Prompt says ## for sections, - for bullets → nbBuild() emits .sec / .subsec / <ul> with one stylesheet. Anything the renderer has no rule for cannot be expressed at all.

after Pass 1 (design) reads a sample of the lecture and invents a visual identity for that subject — a stylesheet, a component vocabulary and an optional script. Pass 2 (body) runs per transcript chunk and writes <section class="page"> fragments using only that vocabulary, drawing diagrams as inline <svg>. The server assembles one standalone document.

Splitting the passes is what makes chunking possible: a whole document cannot be concatenated, but N body fragments sharing one stylesheet can. It is also why this emits HTML rather than JSON — a truncated JSON object loses everything, while truncated HTML still renders every page that arrived.

Try it

The two samples are real generated-shape documents bundled into this page, so they work offline and need no sign-in. Generate calls your live server, which requires a signed-in Pro account and the updated backend deployed.

Same feature, same code path, two lectures — different palette, typography, page furniture and components. That difference is the entire point: it is chosen by the model, not selected from a list.

Requests GET /api/study?id=…&mode=notes&style=html&out=… with Authorization: Bearer <token>. A first run is slow (design pass, then one body pass per chunk) and caches afterwards. If the server returns style: "topic" it is still running the old code.
